## NICE-TO-HAVE

1. **Make D6's precipitation objective finite and fully deterministic before coding it.** Use a prespecified denominator floor with units, or use absolute block-total error in inches; include dry blocks in the same fixed evaluation sample for every method. Define what happens when a normal or prediction is unavailable: report coverage and compare on a common, prespecified set, rather than letting each method discard its failures. Do not choose the floor or loss after inspecting which method wins.

   Read-only verification interpreting "every complete 30-day block" as every daily start in 1956-1985 with all 30 calendar days present and >=25 observed values in each variable found **2,194,588** eligible blocks. `k = floor(N/300) = 7,315`; taking the first 300 phase-0 every-k blocks includes **10 zero-precipitation-total blocks**, including Yuma starting 1961-09-08, Tucson 1974-05-11 and Fresno 1960-12-16. These are observed dry totals, not all-missing blocks. Explicitly say "take the first 300": the untruncated every-k sequence has 301 blocks. If non-overlapping blocks were intended instead, specify their calendar anchor.

2. **Add a conditional chronological check for the actual production forecaster.** Alongside the current R evaluation, select inputs on the inner origins while holding the metric's production `METHOD` fixed, then report the two outer gains for that conditional procedure. Label it conditional because METHOD itself used these historical periods. If it disagrees with the current shipping guard, the simple conservative policy is `official` for that metric. This uses existing predictions and needs no extra weather data or parameter search.

   The distinction is material here: the existing official-input report prefers `last10` for Avg Temp and CDD on the first two inner periods, while production uses `blend`; CDD still prefers `last10` on the first three periods. The new chronological evaluation fixes the earlier leakage concern, but its gain should not be described as direct validation of every production recipe under METHOD.

3. **Report last-year-repeated skill on the same fixed official mask.** Specify a deterministic fallback when the origin year's official value is missing. This is a reference comparison required by the project rules; it need not expand the candidate selection family.

4. **Pin A6's support and ordering.** For example, retain v0's minimum of five common valid years, use up to fifteen nearest years <= origin, break equal-distance ties toward the earlier year, and leave the cell unfilled when fewer than two supported neighbours remain. State that offsets and donor observations use the original pre-infill table, so estimates do not become donors through iteration or city order. Add one sparse-support acceptance case.

5. **Finish H2's small calibration check with existing synthetic tests.** Include no-step cases with 5+5, 5+10 and 10+10 valid years, a gap/missingness case, and autocorrelated noise through both passes; report false adoption and injected-step error. No retuning or exhaustive research is necessary. Keep the current disclaimer that placebo rates do not guarantee a real-change error rate.

6. **Keep filled pairs physically consistent without changing observations.** State how a filled Tmax below an observed Tmin, or a filled Tmin above an observed Tmax, is handled. Clip only the imputed member to the observed member; define a deterministic rule if both are imputed. The v0 midpoint correction changes both members and can violate v4's new observed-value invariant. Add the corresponding assertion case.

The main remaining practical risks are limited temporal replication and model dependence: two outer periods cannot establish performance under every future climate regime or later feature model. The spatial bootstrap measures uncertainty conditional on the chosen periods, and the overall record has already been inspected. Conservative fallback to official inputs remains essential.

Automatic stuck/repeated-rain deletions are supported by neighbours, not proven by independent station records. Local coastal/mountain weather can differ from nearby cities. Early repairs and fragments remain outside the evaluated forecast lookbacks; they should retain the separate QC-evidence claim, not inherit a backtest-success claim. Shared station-network breaks and undocumented changes remain explicit limitations. Late production-only station estimates, filled totals versus incomplete official targets, and sparse/unscored cities still deserve their planned diagnostics.

Keep `fragment_dropped` within the exclusion from official completion and all filling; make the same exclusion explicit for every variable group. Otherwise the new completion policy could accidentally undo A3 despite its "never infilled" requirement. Similarly, distinguish QC invalidation from H-only transition masking when implementing the completion mask.
